# Configuring Policies

Steward's policy engine enforces rules on every agent action. This guide covers all policy types, common patterns, and best practices.

## Policy Basics

Policies are JSON objects with this structure:

```typescript
interface PolicyRule {
  id: string;        // Unique identifier
  type: string;      // Policy type (see below)
  enabled: boolean;  // Toggle without deleting
  config: object;    // Type-specific configuration
}
```

Set policies via SDK or API:

<CodeGroup>
```typescript SDK
await steward.setPolicies("my-agent", [
  { id: "limit-1", type: "spending-limit", enabled: true, config: { ... } },
]);
```

```bash cURL
curl -X PUT https://api.steward.fi/agents/my-agent/policies \
  -H "X-Steward-Key: your-key" \
  -H "Content-Type: application/json" \
  -d '[{ "id": "limit-1", "type": "spending-limit", "enabled": true, "config": { ... } }]'
```
</CodeGroup>

<Warning>
  `setPolicies` / `PUT /agents/:id/policies` **replaces** all policies for the agent. Always include the complete policy set.
</Warning>

## Policy Types Reference

### spending-limit

Controls the maximum value an agent can transact.

| Config Field | Type | Description |
|-------------|------|-------------|
| `maxPerTransaction` | string (wei) | Maximum value per single transaction |
| `maxPerDay` | string (wei) | Maximum cumulative value per 24h rolling window |
| `maxPerWeek` | string (wei) | Maximum cumulative value per 7-day rolling window |

```json
{
  "id": "spending-limit",
  "type": "spending-limit",
  "enabled": true,
  "config": {
    "maxPerTransaction": "100000000000000000",
    "maxPerDay": "1000000000000000000",
    "maxPerWeek": "5000000000000000000"
  }
}
```

<Note>
  Values are in **wei** (1 ETH = 10^18 wei). For Solana, values are in lamports (1 SOL = 10^9 lamports). Steward tracks cumulative spend per agent.
</Note>

### approved-addresses

Whitelist of addresses the agent can send transactions to.

| Config Field | Type | Description |
|-------------|------|-------------|
| `addresses` | string[] | List of allowed destination addresses |

```json
{
  "id": "dex-whitelist",
  "type": "approved-addresses",
  "enabled": true,
  "config": {
    "addresses": [
      "0x1111111254EEB25477B68fb85Ed929f73A960582",
      "0xDef1C0ded9bec7F1a1670819833240f027b25EfF"
    ]
  }
}
```

### auto-approve-threshold

Transactions below this value are auto-approved; above enters the approval queue.

| Config Field | Type | Description |
|-------------|------|-------------|
| `maxValue` | string (wei) | Maximum auto-approve value |

```json
{
  "id": "auto-approve",
  "type": "auto-approve-threshold",
  "enabled": true,
  "config": {
    "maxValue": "50000000000000000"
  }
}
```

### rate-limit

Controls transaction frequency.

| Config Field | Type | Description |
|-------------|------|-------------|
| `maxPerMinute` | number | Max transactions per minute |
| `maxPerHour` | number | Max transactions per hour |

```json
{
  "id": "rate-limit",
  "type": "rate-limit",
  "enabled": true,
  "config": {
    "maxPerMinute": 10,
    "maxPerHour": 100
  }
}
```

### time-window

Restricts when the agent can transact.

| Config Field | Type | Description |
|-------------|------|-------------|
| `allowedHours.start` | number (0-23) | Start hour |
| `allowedHours.end` | number (0-23) | End hour |
| `timezone` | string | IANA timezone (e.g., "UTC", "America/New_York") |

```json
{
  "id": "trading-hours",
  "type": "time-window",
  "enabled": true,
  "config": {
    "allowedHours": { "start": 8, "end": 22 },
    "timezone": "UTC"
  }
}
```

### allowed-chains

Restricts which blockchain networks the agent can use.

| Config Field | Type | Description |
|-------------|------|-------------|
| `chainIds` | number[] | List of allowed chain IDs |

```json
{
  "id": "chains",
  "type": "allowed-chains",
  "enabled": true,
  "config": {
    "chainIds": [8453, 1, 42161]
  }
}
```

### contract-allowlist

Fail-closed transaction-shape control for EVM signing. Restricts the agent to a fixed set of (contract, function selector) pairs and, optionally, caps or allowlists decoded arguments. Use this for any key that can mint, deploy or move value on a specific contract.

| Config Field | Type | Description |
|-------------|------|-------------|
| `contracts` | array | Non-empty list of allowlisted contracts (below) |
| `contracts[].address` | string | Contract address (`0x` + 40 hex). Matched case-insensitively against `to` |
| `contracts[].selectors` | string[] | 4-byte selectors (`0x` + 8 hex) permitted on this contract |
| `contracts[].constraints` | object | Optional per-selector constraints keyed by selector |
| `allowNativeTransfer` | boolean | Permit empty-calldata value transfers to listed addresses. Default `false` |
| `maxNativeValueWei` | string (wei) | Max `value` on any request. Default `"0"` |

Per-selector constraints (only valid on selectors the engine can decode):

| Selector | Function | Constraints |
|----------|----------|-------------|
| `0x40c10f19` | `mint(address,uint256)` | `maxAmount`, `recipientAllowlist` |
| `0xa9059cbb` | `transfer(address,uint256)` | `maxAmount`, `recipientAllowlist` |
| `0x095ea7b3` | `approve(address,uint256)` | `maxAmount`, `recipientAllowlist` (the spender) |
| `0x23b872dd` | `transferFrom(address,address,uint256)` | `maxAmount`, `recipientAllowlist` (the `to` arg) |
| `0x0bab7086` | `createDealToken(string,string,address,bytes32)` | `adminAllowlist` (the `admin` arg) |

`maxAmount` is a uint256 decimal string in the token's base units. Allowlists are case-insensitive address arrays.

Every decision is deny-by-default:

- `to` not in `contracts` → deny
- calldata malformed or shorter than 4 bytes → deny
- selector not listed for that contract → deny
- constraint present but the calldata does not decode to the canonical ABI shape (truncated, trailing bytes, non-zero address padding, bad dynamic offsets) → deny. Constraints are never silently skipped
- empty calldata → deny unless `allowNativeTransfer: true`
- `value` above `maxNativeValueWei` → deny (default cap is `0`, so contract calls cannot carry ETH)
- config fails validation → rejected with `400` on write, and denied at sign time if a bad config is already stored

A selector listed **without** constraints is allowed regardless of its arguments; the engine does not need a decoder for it.

```json
{
  "id": "minter-shape",
  "type": "contract-allowlist",
  "enabled": true,
  "config": {
    "contracts": [
      {
        "address": "0xfac70120000000000000000000000000000000f1",
        "selectors": ["0x0bab7086"],
        "constraints": {
          "0x0bab7086": { "adminAllowlist": ["0x5afe00000000000000000000000000000000005a"] }
        }
      },
      {
        "address": "0xdea1700000000000000000000000000000000d7e",
        "selectors": ["0x40c10f19"],
        "constraints": {
          "0x40c10f19": {
            "maxAmount": "1000000000000",
            "recipientAllowlist": ["0x5afe00000000000000000000000000000000005a"]
          }
        }
      }
    ]
  }
}
```

<Note>
  The evaluator sees `to`, `value` and `data` exactly as submitted to `POST /vault/:agentId/sign`. It is not applied to `/sign-typed-data`, `/sign-solana` or proxy simulation, which have no EVM calldata to inspect. Combine it with `allowed-chains` so the same contract address cannot be targeted on another network.
</Note>

## Common Patterns

<Accordion title="Deal-token minter (factory + token, fixed admin, capped mint)">
A production key that deploys deal tokens through a factory and mints them to a treasury Safe. The key can do exactly two things: call `createDealToken` with the Safe as admin, and `mint` at most `maxAmount` per transaction to the Safe. Anything else (other contracts, other functions, other recipients, larger amounts, ETH transfers) is rejected before signing.

```typescript
const FACTORY = "0x...";   // DealTokenFactory
const DEAL_TOKEN = "0x..."; // DealTokenV1 instance (add one entry per live token)
const TREASURY_SAFE = "0x...";

const dealTokenMinter = [
  {
    id: "minter-shape", type: "contract-allowlist", enabled: true,
    config: {
      contracts: [
        {
          address: FACTORY,
          selectors: ["0x0bab7086"], // createDealToken(string,string,address,bytes32)
          constraints: { "0x0bab7086": { adminAllowlist: [TREASURY_SAFE] } },
        },
        {
          address: DEAL_TOKEN,
          selectors: ["0x40c10f19"], // mint(address,uint256)
          constraints: {
            "0x40c10f19": {
              maxAmount: "1000000000000", // 1,000,000 units at 6 decimals
              recipientAllowlist: [TREASURY_SAFE],
            },
          },
        },
      ],
      // defaults, spelled out: no plain ETH transfers, no ETH on contract calls
      allowNativeTransfer: false,
      maxNativeValueWei: "0",
    },
  },
  {
    id: "chains", type: "allowed-chains", enabled: true,
    config: { chains: ["eip155:8453"] }, // Base mainnet only
  },
  {
    id: "rate", type: "rate-limit", enabled: true,
    config: { maxTxPerHour: 20, maxTxPerDay: 100 },
  },
];

await steward.setPolicies("prod-minter", dealTokenMinter);
```

When a new deal token is deployed, add its address as another `contracts` entry and resubmit the full set. The per-transaction `maxAmount` is a shape control, not a running total; pair it with an operational review of minted volume.
</Accordion>

## Reading Policies

```typescript
const policies = await steward.getPolicies("my-agent");
console.log(policies);
// [
//   { id: "spending-limit", type: "spending-limit", enabled: true, config: { ... } },
//   { id: "approved-addrs", type: "approved-addresses", enabled: true, config: { ... } },
// ]
```

## Disabling a Policy

To temporarily disable a policy without removing it, set `enabled: false` and resubmit the full set:

```typescript
const policies = await steward.getPolicies("my-agent");
const updated = policies.map(p =>
  p.id === "time-window" ? { ...p, enabled: false } : p
);
await steward.setPolicies("my-agent", updated);
```
